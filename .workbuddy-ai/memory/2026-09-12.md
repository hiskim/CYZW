# 2026-09-12

## 修复「切回页面画面显示不全 / UI 贴图丢失」

排查 commit 5ee5f3d（webkit 改善内存占用和释放）引入的问题。

### 结论：根因不在 JS 释放，在 SwiftUI 层

- `ios-cocos/cocos-project/src/ios2-web-boot.js` 的激进释放其实已被后续提交
  （e8b7ac7 / 582bcd9 / bfc29d5）门控住：`releaseUnusedAssets()` 只在
  `assetReleaseState.shuttingDown` 时执行，页面切换不释放。
- 真正的元凶：`MacMultiOpenManagerView.matrixCanvas` 用 `ScrollView + LazyVGrid`。
  懒加载容器只实例化可视区格子，卡片滚出即销毁 `NSViewRepresentable` →
  `dismantleNSView` → `stop()` → WKWebView + WebGL 上下文被拆；滚回来等于重新加载
  整个游戏 → 表现为「部分 UI 贴图丢失 / Canvas 画面被裁切」。多开不限数量时必现。

### 改动

**JS（安全无害释放，按官方 release-manager 文档）**
- `main.js`：移除 `ios2RunNativeSoftCleanup` 里手动调用的
  `cc.Object._deferredDestroy()`。引擎 `Director.mainLoop` 每帧末已自动执行
  （`ios2-web-cocos2d.js:17098`），页面切换瞬间强推会提前销毁交接中的对象。
- `ios2-web-boot.js`：`runRuntimeSoftCleanup` 同样移除强制 `_deferredDestroy()`。
- `ios2-web-boot.js`：`shutdownGame()` 的 `releaseAll()` → `releaseUnusedAssets()`
  （只释放引用计数为 0 的游离资源），删掉 catch 分支里重复的 `releaseAll()`。

**SwiftUI（实例常驻，根治渲染管线损坏）**
- 新增 `MacGameInstancePool`：按 account.id 持有 `MacWebKitGameView`，格子只借用不拥有。
- 新增 `MacGameSurfaceHostView`：`bind/unbind` 挂接/归还画布；`layout()` 同步 frame。
- `MacEmbeddedGameView` 改为返回宿主视图，`dismantleNSView` 只 `unbind()` 不 `stop()`。
- `matrixCanvas`：`LazyVGrid` → 新增的 `MacMatrixGrid`（VStack+HStack 按行 eager 构建）。
- 刷新按钮先 `MacGameInstancePool.shared.reload(accountID:)` 再翻 `reloadKey`。
- `WorkspaceViewModel.close(id:)` 里调 `MacGameInstancePool.shared.destroy`，唯一真正的销毁点。

已 `xcodebuild` 验证 BUILD SUCCEEDED；已把 ios2-web-boot.js 同步进
`ios/Shell/build/Debug/IOS2-Mac.app`（该产物是 git 跟踪的）。

### 第二轮加固

- `MacMatrixGrid.Row.id` 从「本行首实例 id」改为**行号**：关掉一个账号时后面实例
  整体前移，按首实例取身份会导致之后每一行 id 全变、整行格子重建；用行号则只有
  真正跨行的那一个实例会重建。
- `MacGameSurfaceHostView.applyFrame(to:)`：忽略零尺寸 bounds。把 0×0 交给
  WKWebView 会让 WebKit 丢弃 layer backing store，是「画面被裁切」的第二成因；
  首次挂接时先给 270×480（9:16）占位。

### 关键事实（排查过，别再重复查）

- 引擎 `ios2-web-cocos2d.js` 里 `webglcontextlost` 监听数 = **0**，引擎完全不处理
  上下文丢失。
- `device._restoreTexture(unit)` 只是 `bindTexture` 缓存的 `_glID`，不会重建/重传。
- Cocos 默认 `CLEANUP_IMAGE_CACHE`：纹理上传后丢掉 `_image` 源数据。
  ⇒ **真丢上下文时普通 PNG/WebP 贴图无法恢复**，只能靠「不让它丢」。
  若要支持恢复，得显式保留源数据（内存代价）或丢上下文后重建实例。

### 遗留 gap（未修）

WebGL 上下文真丢失时，现有 PVR 恢复只覆盖 ASTC/PVR 纹理
（`scheduleASTCPVRRecovery`），PNG/WebP 等普通纹理没有源字节可重传，仍会丢。
彻底做法是把非压缩纹理的源数据也缓存一份，或接业务侧 AutoDisposeV2。
