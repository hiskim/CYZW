## 修复：游戏内配置（省电模式等）无法保存（同日）
- 现象：账号登录成功后在游戏里改配置，下次登录全部回到默认。
- 根因：`MacWebKitGameView.makeWebView()` 里 `configuration.websiteDataStore = .nonPersistent()`。游戏设置写在 `window.localStorage`（`cc.sys.localStorage` 就是它，见 ios2-web-cocos2d.js 44063），non-persistent 只存在内存，关窗/矩阵实例重建即清空。
- 修复（均在 `ios/Shell/MacWebKitGameWindow.swift`）：
  1. 新增 `MacGameDataStore`：按账号文件名（`Account.id`）用 SHA256 派生稳定 UUID，`WKWebsiteDataStore(forIdentifier:)` → 持久化且账号隔离；`.default()` 会串号故不用。带回退开关 `ios2.gameStorage.persistentDataStore`（默认 true）。
  2. 新增 `MacGameSettingsStore`（单例，Application Support/GameStorage/<账号>.json）：atDocumentStart 注入 restoreScript（仅补 localStorage 缺失键）+ hook `Storage.prototype.setItem/removeItem` 经 `ios2Game` 消息实时回传原生，1s debounce 落盘；didFinish 起 20s 全量快照兜底；stop()/app 终止时 flush。
  3. 单条 value > 256KB 不镜像（资源缓存不算配置）。
- 已知隐患：iOS 版 `WebKitInstance.configureWebView()` 第 215 行同样是 `.nonPersistent()` 硬编码，`policy.allowsStorage` 只管 JS 访问不管持久化；未改（iOS 多开串号风险需先定策略）。
- BUILD SUCCEEDED。

## 多开矩阵自动适配尺寸（9:16 严格比例，同日）
- 需求：自动模式下、用户没手动调过尺寸时，卡片要跟随大厅矩阵可视区自动适配；游戏画面严格 9:16；单实例优先吃满高度、其次吃满宽度；多实例时按「最大高度反推的宽度不超可用宽就按高度适配」；算法要快。
- 新增 `ios/Shell/MacMatrixFit.swift`（纯算法、无 UI 依赖，可单独 swiftc 跑数值验证）：
  - 模型：卡片 = 38pt 头部条 + 游戏画面（宽:高 = 9:16，高 = 宽×16/9）；间距 14。
  - 闭式解 + 单调剪枝：对每个候选列数 c（rows=ceil(n/c)），cardWidth = min((W-s(c-1))/c, ((H-s(r-1))/r - 38)×9/16)，取最大；因「按宽分配」随 c 单调递减，一旦它 ≤ 当前最优立即 break → 迭代次数≈最优列数，几十实例也是微秒级。
  - `fit()` 自动 / `manual()` 手动（沿用旧的首选宽度+列内收缩），均返回同一 `MacMatrixLayout`（columns/rows/cardWidth + gameHeight/cardHeight/gridWidth/gridHeight）。常量：min 96 / max 720 / safetyMargin 1。
  - `MacMatrixCanvasMetrics` 统一画布留白口径（外 24×2+底 20、内 16），`contentSize(from:)` 把测量到的外框换成真正可摆卡的区域。
- `MacMultiOpenManagerView.swift` 接入：
  - `@AppStorage("ios2.matrix.autoSize") isAutoSizing = true` + `@State canvasViewport`（画布区 GeometryReader 经 `MatrixViewportKey` preference 上报，0.5pt 阈值防抖动重排）。
  - `matrixLayout` 计算属性统一出布局；workspace 改成 VStack + header + GeometryReader（原整块 GeometryReader 内嵌 header 的写法已废）。
  - 头部读数 `sizeReadout`（自动/手动 + 实际 WxH）+ ±（点了就切手动，以当前实际宽度为起点）+ 自动/手动胶囊（`MatrixModeChip`，沿用侧栏胶囊配方 + AppKit hoverHighlight）。
  - 网格按 `layout.gridWidth` 收紧 + `minHeight` = 内容区高 → 水平垂直都居中、恰好放满时不滚动（留白口径：content 高 = 外框 − 52，正好等于 ScrollView 可视高）。
  - `MacGameMatrixCell` 游戏视图改为显式 `.frame(width:height:)`（高由宽反推），删掉 aspectRatio/fit —— fit 模式在父级给定宽高时会留白破坏比例。
- pbxproj 登记 A100/A200...001E。BUILD SUCCEEDED（无告警）。
- 数值抽查（画布 1160×820）：1→439×780（高度吃满 818/820）、2→2列 439、3→3列 377×670（宽度受限）、6→3×2 205、9→5×2 205、12→6×2 181，全部不溢出。

## 多行时顶栏自动收窄（同日，接上条）
- 需求：出现双行（rows ≥ 2）时顶栏高度自动缩小，把高度还给游戏画面。
- 实现：`MacMatrixFit` 顶栏高度变成分行函数 `headerHeight(forRows:)`（单行 38 / 多行 26），并**参与求解**——卡片宽度是按「行可用高 − 顶栏」反推的，顶栏每减 1pt 画面就多 0.5625pt 宽（26 档比 38 档：每张卡画面宽 +6.75pt、高 +12pt）。
- 列数扫描里按候选行数取对应顶栏（wByWidth 与顶栏无关，单调剪枝仍成立）；`MacMatrixLayout` 新增 headerHeight 字段；`MacGameMatrixCell` 新增 headerHeight 参数 + `isCompactHeader`（顶栏 26 时序号磁贴 16、昵称 11、图标 font 10、内边距 8）。
- 数值（1160×820，行数为判定条件版本）：n≤5 单行 38 档不变；n=6/8/9 → 26 档 211（原 205）；12 → 181（不变，宽度受限）；全部不溢出。BUILD SUCCEEDED。
- **修正判定条件（用户实测未收窄）**：原实现按「rows ≥ 2」收窄，但双开在宽窗口下是 1 行 × 2 列，永远不触发 → 改为**按实例数判定**：`headerHeight(forInstanceCount:)`，单开 38pt、多开（count ≥ 2）一律 26pt。改后（1472×1010）：2 开 552×981（原 546×971）；单开仍是 546×971。BUILD SUCCEEDED。
- **最终定档（用户要「正常模式也要小、2 行更小」）**：`MacMatrixFit` 顶栏改三档，判定 `headerHeight(forInstanceCount:rows:)` = 单开 32 / 多开单行 24 / 多开 ≥2 行 20（两层条件缺一不可：只看行数的话双开 1 行触发不了）。列数扫描里按候选行数取档（wByWidth 与顶栏无关，剪枝仍成立）。`MacGameMatrixCell` 按 `HeaderDensity`（regular/compact/dense）收档：序号磁贴 20/16/14、昵称 12/11/10、图标 11/10/9、内边距 9/7/5、状态点 7/5。
- 数值（1472×1010）：1 开 549×976；2 开 554×985；6/8 开（2 行）268×476（原 264×469）。全部不溢出。BUILD SUCCEEDED。
