需求：为 macOS SwiftUI + WKWebView 游戏多开管理器加入账号分组管理，左侧侧边栏由扁平列表改为 DisclosureGroup 树形分组。

## 高度卡住的真因与修复（第二轮）

用户实测：仅删根级 minHeight 后高度仍卡在某个尺寸。
真因：`.windowResizability(.contentMinSize)` 把窗口最小高度绑定到**内容固有最小高度**——侧栏顶部固定控件（标题/分区按钮/控制按钮/搜索框/标签云/状态条）约 400pt，不在滚动区、压不扁，成为实际下限。
修复：根视图 `.frame(minWidth: 1000, minHeight: 0)`——**显式 minHeight: 0 覆盖内容固有最小高度**（漏写时 frame 回退用子视图 min，这是关键坑）。高度过矮时底部内容由窗口边缘裁剪，符合 AppKit 自由缩放习惯。
- 通用经验：SwiftUI 里想让窗口高度完全自由，根 frame 必须显式 `minHeight: 0`，仅"不写 minHeight"没用。
- xcodebuild 验证 BUILD SUCCEEDED。

## 修复：毛玻璃重构的编译错误（第二轮）

Xcode 报错 `cannot find 'TitleBarDragRegion' in scope` + 级联的 `Cannot infer contextual base in reference to member 'infinity'`。

根因一：上一轮漏执行了文件末尾 `TitleBarDragRegion` 结构体的 Edit（body 已引用、定义没写），`.infinity` 报错是符号缺失后类型推断断裂的级联错误。
根因二（补上定义后暴露）：`NSView.mouseDownCanMoveWindow` 在 Swift 里是**只读属性**，`view.mouseDownCanMoveWindow = true` 报 "cannot assign to property: 'mouseDownCanMoveWindow' is a get-only property"——必须子类化重写：

```swift
private final class DragRegionView: NSView {
    override var mouseDownCanMoveWindow: Bool { true }
}
```

流程教训：
- **管道掩盖退出码**：`swiftc ... 2>&1 | head -40` 的 `$?` 是 head 的 0，swiftc 实际失败且错误排在 40 行警告之后被截掉。正确姿势：输出重定向到文件（`> log 2>&1`）后单独 `echo $?`，再 grep "error:"。
- typecheck 用 `-target x86_64-apple-macos26.0` 与 Xcode 构建一致；补定义并子类化重写后，同文件清单 typecheck EXIT=0 零错误，警告全部为既有（AccountLibraryView actor-isolation ×12、SettingsView onChange 弃用 ×2）。

## 毛玻璃第六轮：六步配方重做（用户设计反馈）

用户判定上一版"不好看，不是颜色问题"：原稿是「深蓝底+不透明面板+1px 灰边」的后台管理观感；**玻璃成立的前提是背后有可折射的内容**——均匀深蓝上叠透明面板只会变灰板。流程反过来：先铺氛围光，再做玻璃。用户给出六步配方卡（01 底层氛围光：深底+3–5 个超大径向色斑 蓝#3B82F6/紫#8B5CF6/青#22D3EE 30–60%；02 玻璃填充 白 4–7%；03 背景模糊 24–50px，层级越高模糊越大：侧栏/面板 50、卡片 28、浮层 24；04 1px 描边 白 10–14% Inside；05 内高光 白 8–18% y=1 blur=1；06 外投影 黑 35–40% y16–22 blur34–56 spread−8~−14）。核心规则：**模糊差值本身就是层级语言**。

实现映射（MacMultiOpenManagerView.swift，typecheck EXIT=0）：
- 图层结构改为三层 ZStack：L0 `AmbientGlowBackground`（近黑底 #04060C + 5 个 RadialGradient 色斑，错落布点避免叠成均匀色）→ L1 玻璃面板层（侧栏 `.thinMaterial`+白 6%、大厅 `.thinMaterial`+白 4%，右缘 1px 上亮下暗描边、窗口顶边 1px 内高光、侧栏投影黑 40% r22 x6）→ L2 内容层（原样）。
- `GlassCardModifier`/`.glassCard()`：白 5% 填充 + ultraThin + `strokeBorder` 渐变描边（白 .16→.10→.07，顶边亮=内高光，等效配方 04+05）+ 投影黑 38% r20 y18。material 参数可传 nil（叠在已模糊面板上的小卡片省一层模糊合成）。
- 游戏卡片：白 5% 填充（**不加材质**——WebView 铺满卡面、玻璃只在圆角缝隙可见，12 个卡片×材质纯耗 GPU）+ 渐变描边 + 配方投影；青色卡片头降为 opacity 0.45 tint 保留品牌色。圆角 9→12 (.continuous)。
- EmptyMatrixView 用完整 glassCard（面积大，材质真显效）。
- SwiftUI 映射取舍：系统材质无逐层 blur 半径 → 用材质档位近似（thin≈50、ultraThin≈28/24）；负 spread 无对应 API，用紧凑阴影近似；Inner Shadow 用渐变 strokeBorder 等效。
- 氛围光是静态径向渐变，不加动画——3 个 WKWebView 实例 + 毛玻璃已吃 GPU，动效会让材质每帧重采样；想要呼吸感再单独加低频 drift。

## 磨砂玻璃第四轮：对齐参考稿（用户实测「没有明显毛玻璃」后）

用户给了资料库参考图（网页游戏中控台_磨砂玻璃版_主窗口.png，drive 节点 NcbTMpHzMXJHsjCt5bgqyy）。
**根因**：`workspace` 的 ScrollView 还挂着一层 `Color(red:0.075,0.095,0.135)` 不透明背景（第一轮只删了面板层那份，ScrollView 这份漏了），把整个大厅区的氛围光+材质全部盖死——玻璃再对也透不出来。教训：**改背景必须 grep 全文件所有 `.background(Color`，不能只改记得的那份**。
重构（对齐参考稿结构）：
- 大厅区撤掉整面 `.thinMaterial`——参考稿主区是「裸氛围光」，玻璃只属于侧栏+画布容器。
- `workspace` 重排：顶部控制条移出 ScrollView 固定在氛围光上（`.padding(24/14/12)`）；新增 `matrixCanvas` 玻璃画布容器（圆角 14：ultraThin + AmbientRefractionTint + 黑 16% 压暗 + 白 4%，描边/投影挂 background 外），卡片矩阵和空状态装在里面，内边距 16。
- `AmbientGlowBackground` 加饱和对齐参考稿：靛蓝 6366F1 80%/左、紫 8B5CF6 62%/中下、青 22D3EE 55%/右缘、蓝 45%/顶部、亮紫 A855F7 45%/左下，底色 020710 系。
- 新增 `AmbientRefractionTint`（折射增压）：氛围光主色斑低透明度（12–16%）再叠到玻璃表面——系统材质对窗内内容采样强度因系统版本而异，这层保证玻璃必然吃进颜色。
- 侧栏玻璃改为 thin + 黑 30% 压暗 + 折射增压 + 白 5%；卡片头部条青 tint → 黑 45%；卡片投影收敛 y12/r16/35%。
- 卡宽计算 availableWidth 48→80（容器外 24×2 + 内 16×2）。
- 参考稿底部「同步操作」栏是未实现的功能，未伪造。typecheck EXIT=0 零错误。

## 磨砂玻璃第五轮：画布暗板修复（用户截图反馈）

用户截图：侧栏紫玻璃已成立，但画布容器是一块暗板。
双根因：① 五个色斑全贴窗口边缘，画布正后方（窗口中部）是「色斑真空」，blur 近黑 = 暗板；② **文件里 canvasGlass 的 black 被手改成 0.36（我写的是 0.16）、描边首档也 0.36**——用户实测前自己调过参数，36% 黑 + 材质深灰 = 双重压暗。
修复：氛围光在 (0.55,0.38) 补一盏紫 820r 主光（画布正后方）、青 0.62/顶蓝 0.52 加强；折射增压改 4 斑覆盖表面中心（0.14–0.22）；canvasGlass 黑 0.36→0.08、白 0.05；描边首档 0.18；EmptyMatrixView 改 material: nil（画布内双层材质只会更暗）。
教训：**改参数前先 grep 现值**——用户会自己调数值，别假设文件还是自己上轮写入的状态。

## 磨砂玻璃第六轮：紫改深蓝

用户反馈紫色与账号区颜色不配 → 全部紫色系（6366F1 靛/8B5CF6 紫/A855F7 亮紫）换成深蓝系：2563EB 左主光、1D4ED8 画布后主光、1E40AF 底部藏蓝、0EA5E9 左下天青；青 22D3EE 右缘与蓝 3B82F6 顶部保留。折射增压同步换色并微调浓（0.22/0.26）补偿深蓝偏暗。玻璃结构不动。typecheck EXIT=0。

## 磨砂玻璃第七轮：底色加深 + 模糊升档

用户要求背景更深暗蓝、毛玻璃更糊。① 氛围光底色从近黑 020710 系换成真·深海军蓝 #070F22（0.03/0.07/0.16），色斑浓度整体回调 ~12%（0.68/0.55/0.48 档）——底变蓝后光只需做「深蓝里的光」；② glowBlob 改三段式衰减（实→40%→0），色斑边缘更奶；③ canvasGlass 材质 ultraThin→thin（blur 28→50 档），黑压暗 0.08→0.04 补偿 thin 的不透明度。typecheck EXIT=0。

## 磨砂玻璃第八轮：再压暗

用户仍觉不够暗。底色 #070F22 → #040A1A（0.015/0.04/0.10，渊黑蓝），色斑浓度再乘 ~0.85（0.58/0.47/0.42 档）。折射增压保持不动——面板的「色」全靠它，动它玻璃就灰了。typecheck EXIT=0。底线备忘：底色再暗也不能低于 #030813，否则光斑全灭、玻璃又没东西可折射（第四轮教训）。
