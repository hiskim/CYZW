## macOS 滑动删除卡片无法取消的 bug 修复

用户反馈：侧栏账号卡片向左拖出删除按钮后，删除按钮一直显示，向右拖动无法收起。

根因（`MacMultiOpenManagerView.swift` 的 `AccountManagerRow`）：`.allowsHitTesting(!isDeleteRevealed)` 在删除按钮显示态把整个卡片内容层禁用，而 DragGesture 恰好挂在同一层——手势收不到任何事件，向右拖永远无效。

修复：
- 去掉 `.allowsHitTesting(!isDeleteRevealed)`。
- 显示态在卡片上覆盖透明点击层（`.overlay { if isDeleteRevealed { Color.clear...onTapGesture { collapseDelete() } } }`）：点击卡片任意位置即收起删除按钮（对齐 iOS List swipeActions 的「点击行收起」交互）；删除按钮自身 zIndex(2) 在上层不受影响。
- 顺手把 `onEnded` 里易读错的嵌套三元重写为 if/else，语义不变（已显示：向右拖回或几乎没动 → 收起；继续左拖 ≤-24pt → 保持）。
- 验证：xcodebuild Debug build → BUILD SUCCEEDED。

## 高度卡住的真因与修复（第二轮）

用户实测：仅删根级 minHeight 后高度仍卡在某个尺寸。
真因：`.windowResizability(.contentMinSize)` 把窗口最小高度绑定到**内容固有最小高度**——侧栏顶部固定控件（标题/分区按钮/控制按钮/搜索框/标签云/状态条）约 400pt，不在滚动区、压不扁，成为实际下限。
修复：根视图 `.frame(minWidth: 1000, minHeight: 0)`——**显式 minHeight: 0 覆盖内容固有最小高度**（漏写时 frame 回退用子视图 min，这是关键坑）。高度过矮时底部内容由窗口边缘裁剪，符合 AppKit 自由缩放习惯。
- 通用经验：SwiftUI 里想让窗口高度完全自由，根 frame 必须显式 `minHeight: 0`，仅"不写 minHeight"没用。
- xcodebuild 验证 BUILD SUCCEEDED。

4. 弹窗标题同样放宽到两行；卡片水平 padding 12→10。
原则：**窄栏里固定宽度元素（胶囊/开关）用短文案，可变宽度元素（名称）用换行兜底**。

## macOS 脚本管理页紧凑化（磁贴改小 + 卡片统一高度）

用户三点：①两个总开关磁贴太大改小 ②说明文字精简 ③卡片统一高度且名称完整显示。
- **GlobalControlTile 改精简行**：双磁贴（大图标40+标题+说明+开关，~72pt 高）→ 两条竖排开关行（图标28 + 标题13pt + 行尾短状态词 + mini 开关，~46pt 高）。说明文字替换为行尾状态词（运行中/已暂停、多开允许/多开禁止），状态词开启时绿色/关闭转灰；绿光描边保留、shadow 减弱。detail 参数删除，改 onHint/offHint。
- **卡片统一高度**：`.frame(height: 66)` 固定（两行名称32 + 元信息13 + spacing3 + 上下边距16），单行名称内容垂直居中——列表等高整齐；名称 `lineLimit(2)` + `minimumScaleFactor(0.85)` 兜底极端超长。meta 再精简（仅单开/单开+多开/不注入）。
- 说明文字全面精简：头部副标题→「导入的脚本在登录游戏窗口时注入」，暂停横幅→「全局已暂停，脚本暂不注入」。
- 方案要点：**统一高度 = 给"最大内容形态"（两行名+元信息）定额高度，不足者居中**；不用 min-height（会随内容浮动破坏等高）。

## 修复：中控台 账号/脚本/设置 切换按钮要点几次才响应

用户反馈：点击中控台的账号/脚本/设置按钮，经常要点几次才响应。

根因：`.hoverHighlight()` 旧实现 = `@State isHovering + .onHover`。鼠标移入按钮的瞬间（正是按下前一刻）触发 SwiftUI 状态翻转 → 按钮子树在 mouseDown 同一事件周期内被重算换层，macOS 上该 mouseDown 被丢弃；第二次点击时指针已在控件内、不再触发翻转，所以总能成功——与「要点几次」的症状完全吻合。中控台所有按钮都挂了 hoverHighlight，三段切换按钮首当其冲。

修复（MacMultiOpenManagerView.swift）：
1. **HoverHighlightModifier 重写为 AppKit 实现**：`HoverHighlightNSView`（NSView 子类）用 NSTrackingArea（.mouseEnteredAndExited + .activeAlways + .inVisibleRect）检测悬停，高亮直接改自身 layer 背景色（单次 CATransaction 提交），全程零 SwiftUI 状态更新；`hitTest` 恒返回 nil + SwiftUI 层 `allowsHitTesting(false)` 双保险，永不拦截点击。属性 didSet 做等值守卫，updateNSView 重渲染零成本。视觉效果与旧版一致，所有调用点（含 MacScriptManagerView）无需改动。
2. **三段切换抽成独立子视图 `SectionSwitcher`**（private struct，`@Binding var selection`）：父视图任意 @Published 重算 body 时子节点身份稳定、selection 不变不重算；label 加 `contentShape(RoundedRectangle)` 显式命中区域；顺带加 .help。
3. 关键认知：**SwiftUI onHover/@State 悬停效果与点击存在竞态**——悬停翻转恰好落在 mouseDown 事件窗口内就会吞事件；macOS 自定义控件的 hover 一律走 AppKit tracking area，不回写 SwiftUI 状态。
